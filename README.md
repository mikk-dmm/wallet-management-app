# Wallet Management App（家計管理アプリ）

Java / Spring BootとReactを使用して個人開発している家計管理Webアプリケーションです。

家計の予算・支出を記録・管理することを目的としています。実生活での利用に加え、Webアプリケーション全体の構成や処理の流れを体系的に理解するための学習プロジェクトとして開発しています。

バックエンドの設計・実装を中心に、フロントエンドとのAPI連携、データベース設計、Dockerによる環境構築、AWS EC2へのデプロイまで取り組んでいます。各技術の役割や連携を確認しながら、実装・検証・改善を進めています。

## システム構成

```text
ユーザー（ブラウザ）
        |
        | DNS名前解決（DuckDNS）
        v
    Elastic IP
        |
        | HTTPS（TCP 443 / TLS）
        v
    AWS EC2
        |
        v
      Nginx
        | TLS終端
        |
        |-- React（静的ファイル配信）
        |
        |-- API・サーバーサイド画面へのリクエスト
              |
              | HTTP（Docker内部ネットワーク）
              v
         Spring Boot
              |
              | Spring Data JPA / Hibernate
              v
            MySQL
```

Docker ComposeでNginx、Spring Boot、MySQLの3サービスを管理しています。

- Nginxのみ外部公開し、Reactのビルド成果物を配信
- NginxでTLSを終端し、HTTPからHTTPSへリダイレクト
- API・Thymeleaf画面・Spring Bootの静的リソースへのリクエストをバックエンドへ転送
- Spring BootとMySQLはDocker内部ネットワークで通信
- MySQLのデータはDocker Volumeで永続化
- マルチステージビルドによるDockerイメージの構築

## 設計・実装で取り組んだこと

### 1. バックエンドの設計・実装

Spring Bootを使用し、Controller、Service、Repositoryなどの責務を分離して実装しています。

Spring Data JPAを利用したデータアクセスに加え、DTOを用いたAPI設計、入力値のValidation、例外処理、Spring Securityによる認証・認可について学習・実装しています。

それぞれのレイヤーが担う役割や、HTTPリクエストを受け取ってからデータベースへアクセスするまでの処理の流れを確認しながら開発しています。

### 2. フロントエンドとAPIの連携

当初はThymeleafを使用して画面を実装していましたが、支出管理機能についてREST API化を行い、Reactを導入しました。

フロントエンドとバックエンドの責務を分離し、HTTPリクエスト・レスポンスやJSONを介したデータのやり取りについて理解を深めています。

Nginxを利用してReactのビルド済み静的ファイルを配信し、APIリクエストをSpring Bootへ転送しています。

### UI / UX改善

実際のブラウザ操作を通じて、画面間の操作性と表示の一貫性を改善しています。

- カテゴリ・支払い方法の登録、更新、削除時に成功・エラーメッセージを表示
- Spring MVCの`RedirectAttributes`を利用し、リダイレクト後の画面に処理結果を通知
- 共通ヘッダー、操作ボタン、月選択UIの表示を統一
- Dashboardとカテゴリ別予算で前月・翌月への移動、および年月指定による画面切り替えに対応

### エラーメッセージに関する現状と改善方針

現在、カテゴリ・支払い方法の重複登録や削除制約などについては、Service層で例外を発生させ、Controller層で捕捉して画面にエラーメッセージを表示しています。

画面上の操作結果を日本語で分かりやすく伝えるため、現段階では一部のService層の例外メッセージを日本語に変更しています。

ただし、Service層の例外メッセージをそのまま画面表示に利用する構成では、業務上のエラーとユーザー向けの表示文言が密接に結びつきます。

今後は、例外の種類やエラーコードと表示メッセージを分離し、Controller層や共通の例外処理を通じて、画面・REST APIそれぞれに適したエラーレスポンスを返す設計を検討しています。

### 4. データベース設計・管理

MySQLを利用したデータの永続化に加え、Flywayによるスキーマ変更管理を導入しています。

ユーザーごとのデータ管理、テーブル間の外部キー制約、一意制約などを考慮してデータベースを設計しています。

また、支出データの検索・集計処理についてSQLの実行計画を確認し、複合インデックスの設計・検証にも取り組みました。

実行計画を比較し、検索性能だけでなく、インデックス追加による更新処理やストレージへの影響も考慮しています。

### 5. テスト

JUnit、Mockito、MockMvcを使用したテストコードを実装しています。

正常系・異常系の動作や、入力値のValidation、APIのレスポンスなどを確認し、変更による既存機能への影響を検証する仕組みの整備に取り組んでいます。

### 6. Dockerによる環境構築

Docker Composeを利用して、フロントエンド配信・バックエンド・データベースをコンテナ単位で管理しています。

各サービスの役割と通信経路を整理し、データベースやアプリケーションのポートを直接外部公開しない構成としています。

また、Spring Profileと環境変数を利用して開発環境・本番環境の設定を分離しています。

Dockerイメージのビルドとコンテナの起動・再作成の違いや、ビルドキャッシュの動作についても、実際のデプロイ作業を通じて確認しています。

### 7. AWS EC2へのデプロイ・HTTPS化

AWS EC2上にDocker Composeによる実行環境を構築し、HTTPSによる外部アクセスを確認しています。

DuckDNSを利用してサブドメインとEC2のElastic IPを対応付け、Let's Encryptで取得したTLS証明書をNginxに設定しています。

NginxでTLSを終端し、HTTPアクセスをHTTPSへリダイレクトする構成としました。

また、Certbotとsystemd timerを利用した証明書の自動更新処理を設定し、更新テストも実施しています。

画面改善後の本番反映では、HTMLは正常に表示される一方でCSSが404となる問題が発生しました。ブラウザのNetworkタブとNginxの設定を確認し、Spring Bootが配信するCSSへのリクエストをNginxから転送する設定を追加しました。

さらに、Spring BootとNginxのDockerイメージの役割を整理し、変更対象に応じたビルド・デプロイを実施しました。

これらの作業を通じて、DNS、HTTP / HTTPS、TLS、リバースプロキシ、Dockerネットワーク、静的ファイル配信など、Webアプリケーションの公開に必要な技術への理解を深めています。

### 8. デモ環境の構築

第三者が実際にアプリケーションを操作できるよう、デモユーザーとサンプルデータを用意しました。

- BCryptによるパスワードのハッシュ化
- 外部キー制約を考慮したデータ投入
- AUTO_INCREMENTによる主キーの管理
- トランザクションを利用した一括データ登録
- Flywayによるスキーマ管理とデモデータ投入処理の分離
- 本番DBへのデータ投入前のバックアップ

開発環境での動作確認後、本番環境へデータを投入し、公開URLからのログインおよび画面表示を確認しています。

### 9. セキュリティ・運用保守

アプリケーションの公開後も、使用技術に関する脆弱性情報を確認し、影響範囲の調査やセキュリティ更新に取り組んでいます。

2026年11月には、以下の対応を実施しました。

- Java・Nginxなどの脆弱性情報の調査
- 使用バージョン・CPU命令セット・公開構成に基づく影響範囲の確認
- Nginxのセキュリティ更新
- Amazon Linux・Linux Kernelの更新
- Docker Engine・containerdの更新
- ローカル開発環境のJava更新
- 更新後のサービス起動・アクセス確認

脆弱性の検知、影響範囲の特定、優先順位の判断、修正の適用という運用保守の流れを実践しています。

引き続き、依存ライブラリや実行環境のセキュリティ更新に取り組みます。

## 開発目的

本アプリケーションは、バックエンドエンジニアとして必要な技術を実践的に習得することを目的に制作しています。

単に機能を実装するだけでなく、データベース設計、API設計、認証・認可、テスト、環境構築など、Webアプリケーションを構成する各技術の役割と連携を理解することを重視しています。

実装にあたっては、技術や構成の選択肢を確認し、仕組みを学びながら開発を進めています。現在の構成についても、各サービスの役割や通信経路、設計上の判断を自分の言葉で説明できるよう理解を深めています。

また、実際にアプリケーションをインターネット上に公開することで、開発だけでなく、運用保守やセキュリティ管理についても学習しています。

今後もバックエンドを軸に専門性を高めながら、インフラ・セキュリティなどの周辺領域への理解を深めていきます。
